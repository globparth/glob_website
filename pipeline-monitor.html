THE PROBLEM

Bad data is usually found by the person who needed it

A column gets renamed

Someone changes a header in the source system. The report downstream goes blank and nobody knows why.

Half the rows go missing

An export runs before the source job finishes. The numbers look low and decisions are made on them.

Text lands in a number field

One “n/a” in a quantity column breaks the totals for the whole sheet.

Nobody wrote down the fix

The same failure returns next month, and the person who solved it has moved on.

HOW IT WORKS

Four steps for every file

Each pipeline is one regular file moving from a source to a destination, such as a daily sales export feeding a dashboard.

1

Connect

Upload a known-good file once. The monitor learns its columns and proposes the checks: which fields must never be blank, which must be numbers, and which one is the unique key.

2

Run

Drop in each new file, as CSV or Excel. Set how often it is expected, and a pipeline that goes quiet is flagged as overdue.

3

Check

Every run is tested for missing or renamed columns, too few rows, a sudden drop in volume, blanks, duplicates and bad numbers.

4

Fix

A failure comes with its likely cause and a suggested fix. Send the alert to the owner, retry with a corrected file, and record what was done.

WHAT IT DOES

Built for the people who own the numbers

  • One health view across every pipeline, with healthy, warning, failed and overdue states
  • Failures explained with a likely cause, not an error code
  • Clean rows delivered and bad rows held back in a separate file, with the reason for each
  • Alerts written for you and sent from your own WhatsApp or email
  • A searchable audit trail of every run, retry, rule change and resolution, exportable to a spreadsheet
  • Works with your own CSV and Excel files
  • Backup and restore of the whole workspace
